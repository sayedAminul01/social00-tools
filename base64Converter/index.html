What Is Base64, Really?

Base64 is a binary-to-text encoding scheme — it represents any sequence of bytes using only 64 printable ASCII characters. It is not encryption and not compression: it doesn't hide data (anyone can decode it instantly, with no key) and it doesn't shrink data (it actually grows it). Its job is simpler — making binary data safe to carry through systems built for plain text, like email (MIME), JSON, XML, and URLs.

Why Base64 Output Is Always ~33% Bigger

Base64 maps every 3 bytes of input to 4 output characters (each character encodes 6 bits, and 4 × 6 = 24 bits = 3 bytes). When the input length isn't a multiple of 3, the last group is padded with = to complete the block. That fixed 3-to-4 ratio is a mathematical property of the encoding, not an inefficiency in any particular tool — every correct Base64 implementation grows data by the same ~33%.

The UTF-8 Trap: Why Plain btoa()/atob() Fail on Emoji

JavaScript's built-in btoa() and atob() only understand Latin1 — code points 0–255. Feed them an emoji, an accented letter like "é", or any non-Latin script and they either throw InvalidCharacterError or silently mangle the result. This tool avoids that pitfall entirely: text is first converted to raw UTF-8 bytes with TextEncoder, those bytes are Base64-encoded, and decoding reverses the process with TextDecoder — so multi-byte characters always round-trip correctly.

Data URIs: Inlining Files in CSS and HTML

A Data URI embeds a file's Base64 contents directly inside a value, e.g. data:image/png;base64,iVBORw0..., so a browser can render it without a separate network request. It's genuinely useful for small icons, background images, or fonts inlined straight into CSS or HTML — but it isn't free: the ~33% size overhead and loss of browser caching mean it's best reserved for small assets, not full-size images.

Common Real-World Uses of Base64

  • Embedding small images, icons, or fonts as Data URIs in CSS/HTML
  • Sending binary attachments inside JSON or XML API payloads
  • Encoding credentials for HTTP Basic Authentication headers
  • Storing binary blobs safely inside text-based config files or env vars
  • Attaching files to email under the MIME standard

Frequently Asked Questions

What is Base64 encoding?

Base64 is a binary-to-text encoding scheme that represents binary data using only 64 printable ASCII characters (A–Z, a–z, 0–9, +, /). It's used to safely transmit or store binary data in systems designed for text.

Is Base64 the same as encryption?

No. Base64 is not encryption or compression — it provides zero security. Anyone can decode a Base64 string back to its original form instantly with no key required, so never use it to protect sensitive data.

Why does Base64 make output about 33% larger?

Base64 encodes every 3 bytes of input as 4 output characters, and padding rounds shorter groups up to that same 4-character block. That fixed 3-to-4 ratio is what produces the roughly 33% size increase over the original binary.

Why do some Base64 tools break on emoji or accented characters?

Plain btoa() and atob() only understand Latin1 text and will throw an error or silently corrupt anything outside that range, including emoji and accented letters. This tool converts text to UTF-8 bytes first, so multi-byte characters encode and decode correctly.

What is a Data URI and when should I use one?

A Data URI embeds a file's Base64-encoded contents directly inside an href, src, or CSS url() value, like data:image/png;base64,.... It's useful for small images, icons, or fonts you want to inline in CSS or HTML instead of loading as a separate request.

Is anything uploaded when I use this tool?

No. Every conversion, including file encoding and decoding, happens locally in your browser using JavaScript. Your text and files are never sent to any server.
