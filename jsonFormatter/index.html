What Is JSON Formatting & Validation?

JSON (JavaScript Object Notation) is a strict, text-based data format built from objects, arrays, strings, numbers, booleans, and null. "Validating" means confirming the text actually follows that spec — this tool runs it through the browser's own JSON.parse(), the same engine every server and app uses, so a pass here means it will parse anywhere.

Common Mistakes That Break JSON

The usual culprits: a trailing comma after the last item or property, single-quoted strings ('like this') instead of double quotes, unquoted object keys, and // or /* */ comments. All are valid-looking to a human eye but every one of them is rejected by the JSON spec.

Why Pretty-Printing Helps You Debug

Minified JSON from an API response is nearly impossible to scan for a missing brace or a misplaced comma. Indenting it reveals the nesting structure at a glance, so mismatched brackets and misaligned arrays jump out visually instead of hiding in a single unbroken line.

When Should You Minify JSON?

Minify before sending JSON over a network or storing it in a config bundle — stripping whitespace shrinks payload size, which matters for API responses, mobile clients, and build artifacts. Keep the pretty-printed version only while you're actively editing or debugging it.

How This Validator Pinpoints Errors

When JSON.parse() fails, its error message buries a character offset inside a sentence like "Unexpected token } in JSON at position 42". This tool extracts that offset and counts newlines up to it, converting a raw character position into the exact line and column you need to look at.

Frequently Asked Questions

What makes JSON invalid?

The most common causes are trailing commas after the last item, unquoted or single-quoted keys and strings, and comments — none of which the JSON spec allows. Double quotes are required around every key and string value.

Why do JSON keys need double quotes?

The JSON specification only recognizes double-quoted strings. Single quotes, backticks, or unquoted keys are valid in JavaScript object literals but are not valid JSON, so JSON.parse() will reject them.

Can I put comments in a JSON file?

No. JSON has no comment syntax — not // and not /* */. If you need comments, consider JSON5, JSONC, or YAML, or strip the comments before parsing as plain JSON.

What's the difference between formatting and minifying JSON?

Formatting (pretty-printing) adds indentation and line breaks so nested structures are easy to read and debug. Minifying strips all unnecessary whitespace to produce the smallest possible payload — useful for APIs, configs, and production files.

How do I fix an 'Unexpected token' error?

This tool converts the position JSON.parse() reports into a line and column number so you can jump straight to the problem — it's almost always a trailing comma, a missing quote, or a missing comma between elements.

Is my JSON data sent to a server?

No. Parsing, formatting, minifying, and validation all happen locally in your browser using JavaScript's built-in JSON.parse() and JSON.stringify() — nothing you paste here, including API keys or config values, is ever uploaded or transmitted.
