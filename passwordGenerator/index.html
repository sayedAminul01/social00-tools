Why Length Beats Complexity

Once your password draws from a reasonably sized set of characters, adding length does more to stop an attacker than adding character variety. Every extra character multiplies the number of possible passwords by the size of your character set, while adding a new character type only multiplies it once. A 20-character password of just lowercase letters (2620 possibilities) is dramatically harder to brute-force than an 8-character password mixing upper, lower, numbers and symbols (888 possibilities) — length wins by orders of magnitude. This tool lets you push length up to 64 characters while still layering on complexity for the best of both.

The Math Behind the Entropy Number

Password strength is measured in bits of entropy, calculated as length × log2(character set size). This tool's four character types together give an 88-character set (26 upper + 26 lower + 10 numbers + 26 symbols), and log2(88) ≈ 6.46, so a 16-character password using all of them has roughly 16 × 6.46 ≈ 103 bits of entropy. Each additional bit doubles the number of guesses an attacker needs in the worst case, so 103 bits means roughly 2103 possible passwords — far beyond what any known hardware can realistically brute-force.

Why This Tool Uses Web Crypto, Not Math.random()

JavaScript's Math.random() is a fast pseudo-random number generator built for things like animations and shuffling — it is explicitly not designed to be unpredictable, and its internal state has been shown to be recoverable from enough observed output. A password generator that used it would look random to the eye while being far weaker than its stated entropy suggests. This tool instead calls window.crypto.getRandomValues(), the Web Crypto API's cryptographically secure random number generator — the same primitive browsers use to generate encryption keys — for every single character.

Removing Bias with Rejection Sampling

Mapping a random byte (0–255) onto a character set with a plain byte % charsetSize introduces modulo bias: characters near the start of the set get chosen very slightly more often than characters near the end, whenever 256 isn't an exact multiple of the set size. This tool avoids that with rejection sampling — it draws a random byte, and any byte at or beyond the largest multiple of the character set size that fits within 256 is discarded and redrawn — so every character in the set has a mathematically equal chance of being picked.

Guaranteed Character Variety

Pure randomness occasionally produces a password that happens to skip one of your selected character types entirely — more likely at shorter lengths. After generating, this tool checks the result against every enabled type and, if one is missing, either regenerates the whole password or swaps a random position for a correctly-typed character (still chosen with crypto.getRandomValues(), never a predictable substitution) so the guarantee always holds without weakening the randomness.

Frequently Asked Questions

Is this password generator actually secure?

Yes. Every character is chosen using window.crypto.getRandomValues(), the Web Crypto API's cryptographically secure random number generator — the same class of randomness used for encryption keys, not the predictable Math.random() function. Combined with rejection sampling to remove bias, the output is uniformly random across your chosen character set.

Why not just use Math.random()?

Math.random() is a fast, non-cryptographic pseudo-random number generator meant for things like animations and games. Its internal state can potentially be inferred from enough output, and it was never designed to resist prediction. For anything protecting an account — like a password — that's an unacceptable risk, so this tool exclusively uses the Web Crypto API instead.

Are my generated passwords sent to a server or stored anywhere?

No. Every password is generated entirely inside your browser using JavaScript and the Web Crypto API. Nothing is transmitted over the network, logged, saved to a database, or stored in cookies or local storage — closing this tab makes the password exist only wherever you paste it.

How long should my password be?

Length matters more than complexity once you're past a small alphabet. A 20-character password using only lowercase letters is harder to crack than an 8-character password mixing every character type, because entropy grows with every added character. Aim for at least 16 characters where the site allows it.

What does "entropy" mean, and how is it calculated?

Entropy measures how many guesses an attacker would need in the worst case, expressed in bits. This tool calculates it as length × log2(character set size) — for example, a 16-character password drawn from this tool's full 88-character set (upper, lower, numbers, symbols) has about 16 × 6.46 ≈ 103 bits of entropy, which is Very Strong by our scale.

Should I use a password manager?
