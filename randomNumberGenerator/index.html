Why Math.random() Isn't Good Enough

Math.random() is a fast pseudo-random number generator (PRNG) built for speed, not unpredictability. It's fine for shuffling a UI animation, but its internal state can potentially be inferred or reproduced, which makes it a poor choice for anything where fairness or security actually matters — raffle winners, giveaway draws, or security-sensitive values. This tool uses the Web Crypto API's crypto.getRandomValues() instead, the same randomness source browsers use for generating encryption keys.

What Is Modulo Bias?

A common shortcut for turning a random value into a number within a range is random() % range. The problem: unless the random value's total space divides evenly by your range, some remainders occur slightly more often than others. Over many draws this "modulo bias" quietly skews results toward certain numbers — a subtle bug that looks correct in casual testing but breaks true fairness.

How This Generator Works

Each number is produced by drawing bytes from crypto.getRandomValues() and applying rejection sampling: the tool calculates the largest multiple of your range's size that fits evenly into the drawn value space, and discards (re-draws) any value that lands in the small leftover zone. Every value that survives maps onto your range with exactly equal probability — no bias, no shortcuts.

Unique vs. Repeating Numbers

With "Allow duplicates" checked, each number is drawn independently, so the same value can appear more than once — correct behavior for dice rolls or lottery-style draws. Uncheck it to draw unique values only: the tool keeps generating unbiased numbers until it has exactly the quantity you asked for, with no repeats, and it validates up front that your requested quantity actually fits within the range so it never loops forever.

Anywhere the outcome needs to be genuinely unpredictable and not favor any particular value.

Frequently Asked Questions

Why not just use Math.random()?

Math.random() is a fast pseudo-random number generator (PRNG) designed for speed, not unpredictability. Its output can be predicted or reproduced under certain conditions, which makes it unsuitable for anything where fairness or security matters — raffles, giveaways, security tokens, or games with real stakes. This tool uses the Web Crypto API instead, the same source of randomness used for encryption keys.

What is modulo bias?

Modulo bias happens when you take a random value and reduce it with random() % range to fit a smaller range. Unless the random value's total space divides evenly by your range, some remainders come up slightly more often than others, subtly skewing the results. It's a well-known, easy-to-miss bug in naive random number code.

How does this tool avoid modulo bias?

It uses rejection sampling: it draws random bytes from crypto.getRandomValues(), works out the largest multiple of your range that fits evenly into the byte space, and silently discards and re-draws any value that falls in the leftover "excess" zone. Every remaining value maps to your range with exactly equal probability, so no number is ever favored.

Can I generate unique, non-repeating numbers?

Yes. Uncheck "Allow duplicates" and the tool will draw unbiased random numbers until it has the exact quantity you asked for, with no repeats. If you request more unique numbers than exist in your chosen range, it shows a validation error instead of hanging or silently returning fewer numbers.

What can I use a random number generator for?

Common uses include picking winners for raffles and giveaways, drawing random samples for statistics or research, simulating dice rolls or card draws for games, assigning random IDs or test data, and settling ties fairly.

Is anything I generate sent to a server?

No. Every number is generated locally in your browser using the Web Crypto API. Nothing about your range, quantity, or results is transmitted anywhere or stored.
