What Is a Cryptographic Hash?

A cryptographic hash function takes any input — text, an image, a whole video file — and produces a fixed-length string of characters called a digest. The same input always produces the exact same digest, a single changed byte produces a completely different one, and there is no way to work backward from the digest to recover the original input.

Verifying Downloaded Files

Software publishers often list a SHA-256 checksum next to a download link. After downloading, hash the file with this tool and compare it to the published value: an exact match means the file arrived intact and untampered with, while a mismatch means it was corrupted in transit or altered.

Detecting Duplicate Files

Because identical bytes always produce an identical hash, hashing is a fast, reliable way to spot exact duplicate files without comparing their contents byte-by-byte — useful for cleaning up storage or confirming two copies of a file are truly the same.

MD5 and SHA-1: Broken, but Still Useful

MD5 and SHA-1 are considered cryptographically broken — researchers have demonstrated practical collision attacks, where two different inputs are deliberately crafted to produce the same hash. Neither should be used to protect anything sensitive. They remain widely used for non-adversarial checksums and legacy compatibility, such as Git's commit identifiers, which is why this tool still supports them.

Never Use This for Password Storage

General-purpose hashes like SHA-256 are designed to run as fast as possible, which is exactly wrong for passwords — it makes brute-forcing cheap. Password storage requires a dedicated slow, salted algorithm such as bcrypt or Argon2. This tool does not implement those and should never be used to hash passwords for storage.

Frequently Asked Questions

What is a cryptographic hash?

A one-way fingerprint of your data. The same input always produces the same fixed-length output, but you cannot reverse the output back into the original input, and changing even one character completely changes the result.

Are MD5 and SHA-1 safe to use?

Not for security purposes. Both are cryptographically broken — practical collision attacks exist, meaning two different files can be crafted to produce the same hash. Use SHA-256 or SHA-512 for anything security-sensitive; MD5 and SHA-1 are fine only for checksums and legacy compatibility.

Can I use this to verify a downloaded file?

Yes — switch to File mode, hash the file you downloaded, paste the checksum published by the source into the Compare field, and the tool tells you instantly whether they match.

Why does Git use SHA-1 for commit IDs?

Git uses SHA-1 hashes as content-addressable identifiers for commits, trees, and blobs — a convenient way to detect accidental corruption and duplicate content, not a security guarantee against a deliberate attacker.

Can I use this tool to hash passwords for storage?

No. Password storage needs a slow, salted algorithm designed to resist brute-force attacks, such as bcrypt or Argon2 — this tool only computes fast general-purpose hashes (MD5, SHA-1, SHA-256, SHA-384, SHA-512), which are unsuitable for that job.

Does this tool upload my files or text anywhere?

No. Every hash is computed locally in your browser using the native Web Crypto API (and a local MD5 implementation) — nothing you type or upload ever leaves your device.
