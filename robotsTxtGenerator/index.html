What Robots.txt Actually Does

          
A robots.txt file is a crawling-behavior request, not a security mechanism. It tells cooperative crawlers which paths they may or may not fetch, but it can't stop a browser, a bot that ignores it, or a person from opening a disallowed URL directly. A page you disallow can still get linked to, shared, or even indexed by name if another site points to it — robots.txt only controls crawling, never visibility or access.

        

        

          
Where Robots.txt Must Live

          
The file has to sit at your domain's root — example.com/robots.txt — never in a subfolder like example.com/blog/robots.txt. Crawlers check exactly one location per host (and per subdomain), so a correctly written file placed anywhere else is simply never read.

        

        

          
How This Generator Builds Your File

          
Pick a default policy, then optionally add rule groups for specific crawlers. Rules for the same User-agent — whether from the default policy or a custom group you add — are automatically merged into one contiguous block, exactly as the spec requires; duplicate, non-contiguous User-agent lines for the same bot are invalid syntax that this tool avoids for you.

        

        

          
Crawl-delay: Who Actually Listens

          
Crawl-delay asks a bot to wait N seconds between requests. Googlebot ignores it completely — Google manages crawl rate itself and expects you to use Search Console instead. Bing, Yandex, and a handful of smaller crawlers still honor it, so it remains useful if you're not optimizing purely for Google.

        

        

          
Blocking AI Crawlers Separately From Search

          
AI-training crawlers are a distinct category from search indexers, and increasingly get their own rules: GPTBot (OpenAI), CCBot (Common Crawl), anthropic-ai / ClaudeBot (Anthropic), and Google-Extended (Google's AI-training signal, separate from Googlebot search). You can allow search crawling while blocking AI training, or the reverse, by giving each agent its own group.

Frequently Asked Questions

        

          

            What is a robots.txt file?
            
A plain-text file at your site's root that tells search engine and other crawlers which URLs they may request, using User-agent, Allow, and Disallow directives. It's a request that well-behaved crawlers choose to follow, not an access-control mechanism — it doesn't password-protect anything or stop a page from being viewed directly.

          

          

            Does Disallow keep a page out of Google's search results?
            
Not reliably. Disallow tells crawlers not to fetch a URL, but if other pages link to it, Google can still index the URL itself (sometimes with no description, since it never crawled the content) because it discovered the link elsewhere. To reliably keep a page out of search results, use a noindex meta tag or restrict access, not robots.txt.

          

          

            Where do I upload my robots.txt file?
            
It must sit at your domain root, e.g. https://example.com/robots.txt — never in a subfolder. Crawlers only ever check that one exact location, so a copy at /blog/robots.txt or /en/robots.txt is silently ignored.

          

          

            Does Google honor the Crawl-delay directive?
            
No. Google has stated Googlebot ignores Crawl-delay entirely and relies on its own crawl-rate logic instead. Bing, Yandex, and several other crawlers still respect it, so it's still worth setting if you care about non-Google traffic.

          

          

            Should I block AI crawlers like GPTBot or ClaudeBot?
            
That's a separate decision from search-engine crawling. Site owners increasingly add explicit rules for AI-training crawlers — GPTBot (OpenAI), CCBot (Common Crawl), anthropic-ai and ClaudeBot (Anthropic), and Google-Extended (Google's AI-training crawler, separate from Googlebot search) — to allow or block them independently of Googlebot and Bingbot.

          

          

            Does this tool send my data anywhere?
            
No. Every rule you add and the robots.txt text it produces are generated entirely in your browser with JavaScript — nothing is uploaded, logged, or stored on a server.
