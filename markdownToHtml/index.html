What Is Markdown?

Markdown is a lightweight plain-text formatting syntax created by John Gruber in 2004. Instead of clicking toolbar buttons, you type simple symbols — # for a header, ** for bold — and a Markdown processor turns that plain text into HTML. It's popular precisely because it's write-once, render-anywhere: the same .md file looks right on GitHub, in a static site generator, or pasted into a forum post.

How This Converter Works

The input is split into block-level chunks first — headers, lists, code fences, blockquotes, paragraphs — and only then is each chunk's text run through a second, inline pass that handles bold, italic, links, images, and inline code. This two-pass approach is the standard way to structure a small Markdown parser, and it avoids a lot of the bugs a single giant regex would introduce.

The Supported Syntax at a Glance

ATX headers (# through ######), bold and italic using either **/__ or */_, [links](url), ![images](url), `inline code`, fenced ``` code blocks, flat unordered/ordered lists, > blockquotes, and --- horizontal rules. The note above the input box is the authoritative list.

What's Deliberately Left Out

This is a small hand-written parser, not a CommonMark implementation, so it's scoped honestly rather than claiming full spec coverage. Nested or multi-level lists, tables, footnotes, definition lists, and assorted CommonMark edge cases aren't implemented — for those, reach for an established library instead of this tool.

Why HTML-Escaping Matters for Security

Whatever you type is escaped for HTML-special characters (<, >, &) before any Markdown formatting is applied, so a literal <script> tag or a stray angle bracket in your text becomes inert, visible text instead of live markup. That matters any time rendered output gets inserted into a page's DOM — which is exactly what the live preview does.

Frequently Asked Questions

What is Markdown?

Markdown is a lightweight plain-text formatting syntax created by John Gruber in 2004. You write simple symbols like # for headers or ** for bold, and a Markdown processor converts that plain text into HTML — which is why it's the default format for README files, GitHub comments, forums, and countless note-taking and documentation tools.

Which Markdown features does this converter support?

This tool implements a clearly-scoped subset: ATX headers (# through ######), bold and italic, links and images, inline code, fenced code blocks, flat unordered and ordered lists, blockquotes, horizontal rules, and paragraphs. The supported-syntax note above the input field is the definitive list.

Why isn't everything supported, like tables or nested lists?

This converter uses a small parser written from scratch rather than a full CommonMark library, so it deliberately covers a defined subset instead of claiming full spec compliance. Tables, nested/multi-level lists, footnotes, and some CommonMark edge cases aren't implemented — for those, a dedicated Markdown library is a better fit.

Is it safe to type HTML tags inside my Markdown?

Yes. Any HTML-special characters you type — like <, >, and & — are escaped before formatting is applied, so raw HTML or a pasted <script> tag renders as inert, visible text in the preview instead of running or altering the page. Only the HTML tags this tool generates itself (headers, links, etc.) are ever inserted as real markup.

Is my Markdown text uploaded anywhere?

No. Parsing and rendering happen entirely in your browser using JavaScript running on your device — nothing you type is sent to a server, stored, or transmitted anywhere.

Can I use the raw HTML output on my own website?

Yes. The HTML Source tab shows the exact markup the preview is built from, and the Copy HTML button copies it as-is so you can paste it into a page, CMS, or email template.
