What Is a UUID?

A Universally Unique Identifier (UUID), also called a GUID (Globally Unique Identifier) on Windows and in .NET, is a 128-bit value written as 32 hexadecimal digits split into five groups by hyphens — 8-4-4-4-12, e.g. 3fa85f64-5717-4562-b3fc-2c963f66afa6. It gives you an identifier you can generate anywhere, on any machine, with no central registry or database round-trip required to guarantee it doesn't collide with one already in use.

Why UUIDs Are Practically Unique

A version 4 UUID sets 6 of its 128 bits to fixed version/variant markers, leaving 122 bits of genuine randomness. Applying the classic "birthday paradox" — the same math behind the surprising odds of two people in a room sharing a birthday — to a space that large works out to roughly 2.71 quintillion (2.71 × 1018) randomly generated v4 UUIDs before there's even a 50% chance that any two of them ever match. For any realistic application, the collision risk is negligible.

Version & Variant Bits Explained

Look at a v4 UUID's third group: it always starts with 4 — that's the version nibble, marking "version 4, randomly generated." The fourth group always starts with 8, 9, a, or b — that's the RFC 4122 variant marker, occupying the top two bits of that byte. Every other digit is unconstrained randomness. Those two fixed markers are exactly what the regex ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$ checks for, and every UUID this tool produces satisfies it.

How This Generator Works

Generation uses crypto.randomUUID() where the browser supports it — a native, spec-guaranteed-correct implementation. As a transparent fallback, the same result can be built manually: pull 16 cryptographically random bytes from crypto.getRandomValues(), force the high nibble of byte 6 to 0100 (the version bits) and the top two bits of byte 8 to 10 (the variant bits), then format the 16 bytes as 32 hex characters in the standard 8-4-4-4-12 groups. Both paths use the Web Crypto API — never Math.random(), which is not cryptographically secure.

Real-World Use Cases

  • Distributed-system object and request IDs, without a central ID-issuing service
  • Session tokens and idempotency keys for APIs
  • File names, correlation IDs in logs, and test fixtures that must never collide

Format Options Explained

Some systems have their own formatting expectations for the same underlying 128-bit value: uppercase hex digits (the value is identical, just the letters A–F instead of a–f), no hyphens (a flat 32-character hex string some APIs and databases store more compactly), and braces ({...}), a convention inherited from older Windows and COM interfaces that still shows up in registry keys and some .NET APIs. All three toggles only change presentation — never the underlying random value.

Frequently Asked Questions

What is a UUID?

A Universally Unique Identifier is a 128-bit value, usually written as 32 hex digits in five hyphen-separated groups (8-4-4-4-12), used to identify something without a central authority handing out IDs.

How unique is a random v4 UUID, really?

A v4 UUID has 122 random bits (the other 6 are fixed version/variant bits). Using the birthday-paradox math, you'd need to generate roughly 2.71 quintillion random v4 UUIDs before there's just a 50% chance any two of them ever match.

What do the version and variant digits mean?

In a v4 UUID the first digit of the third group is always "4", marking it as version 4 (random), and the first digit of the fourth group is always 8, 9, a, or b, marking the RFC 4122 variant. Every UUID this tool generates has both set correctly.

Is anything sent to a server when I generate a UUID here?

No. Every UUID is generated locally in your browser using the Web Crypto API. Nothing you generate is ever transmitted anywhere or logged.

Uppercase or lowercase — does it matter?

The RFC 4122 spec recommends lowercase, and most systems output lowercase by convention, but uppercase hex digits represent the exact same value. Use whichever case your target system expects.

Should I use v4 or another UUID version?

Version 4 (fully random) is the practical default for almost every use case today, which is why this tool focuses on it. Other versions encode a timestamp or a namespace hash instead of pure randomness, which is only worth the added complexity for specialized needs.
